# KEVIN'S CREW

The people Kevin works with. Punk-format pixel avatars — one 32×32 grid, every
feature its own layer, generated by `tools/gen-crew.mjs`.

Twenty minted. **8,128,512** combinations available from the trait tables as
they stand, so the twenty are a first drop, not the collection.

```
node tools/gen-crew.mjs              # re-render from the manifest
node tools/gen-crew.mjs --mint 100   # extend to 100 — the first 20 do not move
node tools/gen-crew.mjs --sheet      # also write contact-sheet.png
```

## How adding more works, and why it is safe

Two rules, and everything else follows from them:

1. **A minted token's traits are frozen.** They are rolled once, written to
   `crew.json`, and read back from there forever. Re-rendering never re-rolls.
2. **Trait tables are append-only.** Add to the end of a list in
   `tools/lib/crew.mjs`; never reorder, never delete. Reordering would change
   what an old seed rolls, and rule 1 only holds because rule 2 does.

So a new hat next month gives *new* tokens something more to roll and leaves
every existing character untouched. This is checked, not assumed: adding a
trait and extending 20 → 25 leaves #001–#020 byte-identical in the manifest.

`gen-crew.mjs` also refuses to shrink the set, because that would un-mint
somebody who already holds one.

## The link to the gym

Every trait name is also something the gym can put on a 3D body: a cap is a hat
mesh, a shirt is a texture swap, a crew colour is a material. The traits are the
bridge between the avatar and the playable character — the art style is not, and
does not have to match. Your NFT is a 32×32 pixel avatar and the same character
in the gym is a toon-shaded 3D body wearing the same four things.

That is also why the trait list is worth more than the pictures. Anything added
here has to be buildable there, so keep new traits to head, face, torso and
handheld items.
